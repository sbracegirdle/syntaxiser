# JavaScript depth expansion

Issue #74; implementation baseline `4821341` on main. Baseline: 28 topics, 28 examples, 28 overviews. After: 53 topics, 80 examples, 53 overviews. All original topic/card IDs and lesson progress remain intact. Inventory is not a quality score: the following rows map concrete semantic variants and independent assertions.

## Supported execution contexts

Use Node 26.3.0 from `.nvmrc`; modern ESM throughout. The existing frozen playground lock remains unchanged: React/React DOM 19.3.1, Express 5.3.0, Vitest 5.0.4, Testing Library React 16.3.0, jsdom 30.1.2, Playwright 1.62.1 and esbuild 0.28.2. No upgrade is required. Browser checks use Playwright’s pinned Chromium; runtime evidence records its actual version. Each card states imports, surrounding data and limits. Node paths/files are host APIs; DOM/form/storage cards require a real browser document and origin. JSX needs the documented transform. Tooling commands remain outside language syntax.

## Evidence boundaries and review

Every practical card is parsed/compiled as actual JavaScript/JSX by the existing generator and esbuild path; JavaScript has no TypeScript typecheck claim. All 52 added cards have execution and behavioral registrations. The checker matches the declared cases to assertions actually completed. Original cards retain conservatively registered inspected evidence from their existing runner. Historical missing situations remain visible in the common report rather than being relabelled as passing. In particular constant-binding, basic React, interpolation and similar starter topics do not gain fabricated failure cases. This ticket expands the requested semantic/workflow scope; it does not waive the standard for those historical topics.

Content review: each overview was authored independently from its solved tasks; version-specific APIs match the locked dependencies. Important deliberate limits: shallow spread keeps nested identity, clone cannot serialize functions, WeakMap GC is nondeterministic, Unicode is not confusable detection, floats are not exact money, path checks are lexical without a symlink sandbox, Promise.race does not cancel losers, browser validation does not replace server validation, tab activation is not a complete keyboard widget, forms need a concurrency policy for simultaneous saves. Review these restrictions alongside the task rather than treating them as production frameworks. The [ECMAScript promise algorithms](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise.allsettled) distinguish input-order reporting from first-settlement behavior; assertions use controlled microtask order without elapsed-time expectations.
