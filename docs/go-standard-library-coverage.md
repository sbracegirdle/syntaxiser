`playground/go/standard-library/catalog-checks.json` contains independent assertions and necessary imports, not copies of card implementations. `scripts/check-go-standard-library.cjs` inserts exact catalog text into isolated temporary packages. `legacy-compile.json` supplies minimal documented surroundings for the 26 prior cards; no behavioral credit is assigned for compiling them. The new test mutation regression changes only `sync-counter` catalog text and confirms its independent assertion fails. All cards are gofmt parsed and compiler/vet checked. Runtime evidence registration is scoped to inspected cases; it does not claim all historical Go topics have behavior coverage. Gin/Chi/Testify remain #69.

Review of lesson links: the existing Go sequence already names JSON, file readers, HTTP, context, mutex, testing and benchmarks. Updated lesson learning links point to specific APIs and the local matrix without changing IDs, tasks, completion checks or progress. These examples teach prerequisites rather than solve whole exercises: bounded request bodies/client transport cancellation, reader injection, fuzzing and larger capstones still require learners to combine concepts. The closed-channel policy in `receiveJob` is deliberately a service error; the go-context lesson asks learners to define a different normal-completion policy.

Run and manually inspect the [playground](../playground/go/standard-library/README.md). `check:go` distinguishes parsing, compilation and actual assertions, runs `go test -race`, two one-iteration benchmarks and `go vet`. `audit:runtime go` captures command status/revision/input hashes; extension tests verify two searches and a cursor probe per new area plus aliases, masking, incomplete calls and a catalog mutation. Existing UI tests cover copy/pins/language state. Benchmark smoke execution does not establish performance. Close-error/HTTP-write-error failure injection, full network behavior, JSON duplicate keys and exhaustive historical semantic checks are outside these assertions.
