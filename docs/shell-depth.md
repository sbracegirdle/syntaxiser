# Shell depth and exact-card evidence

Issue #81; baseline origin/main 6b4d81c. The retained catalog had 62 topics, 79 practical cards and 62 separate overviews. This expansion has **82 topics, 119 cards and 82 overviews**: 20 new independently authored topic units with two distinct tasks each. Existing 79 card objects/IDs remain unchanged. Node/AWS breadth, pins and lesson identities survive; only six lesson instructions gain prerequisite reference guidance.

## Toolchain and reproduction

Use nvm/pnpm for Node. The evidence runner checks Bash **5.2.21**, Zsh **5.9**, Git **2.43.0**, jq **1.7**, Node **26.3.0**, GNU findutils **4.9.0**, GNU coreutils **9.4**, sed **4.9**, grep **3.11**, mawk **1.3.4 20240123**, and Debian/Ubuntu dash **0.5.12-6ubuntu5**. A mismatched version reports unavailable rather than silently claiming comparable evidence. This is a Linux reference fixture; BSD/macOS tools and shell releases require a separate run and compatibility review. Cards state narrower POSIX subsets where useful; Bash/Zsh compatibility does not imply native glob/array semantics are identical.

```sh
source ~/.config/nvm/nvm.sh
nvm use
pnpm install --ignore-scripts
pnpm --dir playground/shell/node-cli install --frozen-lockfile --ignore-scripts
pnpm --config.verify-deps-before-run=false check:shell:depth
pnpm --config.verify-deps-before-run=false test
pnpm --config.verify-deps-before-run=false audit:runtime shellscript
pnpm --config.verify-deps-before-run=false audit:coverage --check
node scripts/lesson-coverage.cjs --check
```

Installation needs registry access. All depth tests run offline, use exact pack card text, and create only temporary files/local Git histories. No remotes, production credentials or cloud/deployment commands execute. The retained optional AWS family runs its existing CLI-model tour only if installed. The existing Node family retains its frozen dependency versions (see the shell README); it is required by the full shell runner.

All new units are required in coverage/languages.json; no requirement was removed.

The table maps overview IDs directly to exact card IDs and inspected assertion specifications in playground/shell/depth-cases.json. scripts/check-shell-depth.cjs reads those specifications, executes the exact text, compares stdout/stderr/status and listed file/index/stash outcomes, and checks temporary cleanup. Each card runs happy, meaningful edge and rejection situations in every declared shell. A fourth run reconstructs valid inputs/repository in the same isolated workspace after rejection, then asserts the happy result again. This demonstrates repair by fixture reconstruction; it does not claim every conflict is automatically resolvable in place. Merge/rebase abort and stash-retention checks independently inspect real recovery state.

## Assertion quality and limitations

- Function local isolation is asserted via an outer variable; return permits the caller to continue. Positional/array tests include empty strings, spaces and literal globs. NUL workflows include filenames containing a newline; directory-empty and missing-source outcomes differ.
- Read tests preserve whitespace/backslashes and final unterminated records. Simple colon/delimiter examples are not CSV parsers. awk reports validate fields before arithmetic; sorting tests explicitly document where sorting alone does not validate input.
- grep status 1 is negative data; 2 is a read error. Node composition checks syntax before execution and propagates runtime rejection. Pipeline checks catch failed producers even when the final sort succeeds. Bash PIPESTATUS snapshots and explicit process-substitution waits are separately asserted; no reliance on errexit alone.
- Temp cleanup is observed after both success and copy failure; partial reports must disappear on rejection. Signal handlers are documented, but forced signal delivery and SIGKILL are outside these fixtures. The partial-report task reserves its output filename and is not a concurrent atomic publisher.
- Quoted here-documents retain dollar expressions literally. Separate stderr does not contaminate result output. Substitution tests distinguish stripped versus preserved trailing newlines and retain original sentinel-like dots; shell variables cannot represent NUL.
- jq rejects noninteger arrays and preserves quote/empty-string arguments via --arg. Arithmetic assumes numbers within exact range. Tests do not verify every possible malformed JSON/schema shape.
- Git fixtures construct ordinary and modify/delete conflicts and inspect real index stages, stash recovery copies, current rebase patches and clean abort state. Staging/unstaging checks preserve edited worktree bytes. Only fixture-local Git config changes; global config and signing are disabled. No push, interactive rebase or shared-history rewrite occurs.
- The suite deliberately tests exact practical code, not schematic overviews. Nine meaningful catalog mutations must fail (local removal, argument splitting, nullglob, pipefail, cleanup, sentinel failure masking, partial awk totals, destructive restore, empty jq sum). Historical evidence gaps for old topics remain visible rather than receiving uninspected registrations. New-topic audit findings are zero.
- Editor cue scanning masks quotes, escapes, comments and simple quoted/unquoted here-documents while preserving UTF-16 offsets. It is conservative and does not evaluate shell code, aliases or substitutions inside strings. Function declarations/arrays and inspected command names produce only allowlisted cues; values and paths remain private. Recent edits do not introduce extra shell data. Live Zsh input supports command families; full multi-line structural scanning is provided by editor and executed-command extraction, not the redraw hook.

GNU web manuals timed out in the research fetch; Bash 5.2 builtin help and locally installed manuals plus exact runtime assertions verify the used features. HTTP GET returned 200 for the Bash topics, sort, jq and pinned Git sources; the old findutils URL returned 404 and was replaced with the official indexed Safe File Name Handling page. Full sed/gawk downloads and later GNU HEAD probes timed out, so complete live verification of all GNU links remains a network limitation. HTTP availability does not establish every statement's semantics. GNU online manuals can describe newer releases; the pinned runtime evidence above limits our claims.
